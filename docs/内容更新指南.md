# 题库内容更新指南

正式版题库以 **内容包** 为唯一数据源，应用与题目解耦。日常更新题目不需要改动 `app.js`，重新构建并替换 `bundle.json` 即可。

## 1. 数据流

```text
demo/content/packs/*.json      ← 人工维护（唯一数据源）
        │
        ├─ node scripts/validate-content.js   校验单包
        ├─ node scripts/build-content.js      全量校验 + 生成
        ▼
demo/content/bundle.json       ← 在线运行时加载（可独立更新）
demo/js/data.js                ← 离线/file:// 内置题库（随应用发布）
        │
        ▼
ContentLoader.loadContent()    ← HTTP 优先加载 bundle，失败回退内置
```

- `demo/content/bundle.json` 与 `demo/js/data.js` 是**生成文件，禁止手工修改**。
- 应用启动时在 HTTP 环境下请求 `content/bundle.json`（`cache: no-store`）。远程版本合法且不低于内置版本时使用远程题库；版本更旧、请求失败或数据非法时自动回退内置题库。
- 学习进度只存在浏览器 `localStorage`，与题库版本无关；更新题库不会清空进度。

## 2. 目录与文件

| 路径 | 作用 |
| --- | --- |
| `demo/content/manifest.json` | 内容版本、发布日期、更新说明、内容包列表 |
| `demo/content/packs/<topic>.json` | 单个主题的课程与题库 |
| `demo/content/SCHEMA.md` | 字段、数量、难度与质量规范 |
| `demo/content/bundle.json` | 构建生成的运行时题库 |
| `demo/js/data.js` | 构建生成的内置题库（UMD） |
| `scripts/validate-content.js` | 校验单个/全部内容包 |
| `scripts/build-content.js` | 校验并生成上述两个文件，`--check` 只检查是否过期 |

## 3. 常规更新流程

1. **改内容**：编辑 `demo/content/packs/<topic>.json`。字段与深度要求见 `SCHEMA.md`。
2. **改版本**：更新 `manifest.json`：
   - 增加/删除/重写题目：`contentVersion` minor +1（如 `2.0.0 → 2.1.0`）
   - 只修正错别字/解析措辞：patch +1（`2.1.0 → 2.1.1`）
   - 增删主题、调整结构或不兼容字段：major +1（`2.1.0 → 3.0.0`）
   - 同步更新 `releasedAt` 与 `notes`（面向用户的一句话说明）。
3. **校验**：
   ```bash
   npm run content:validate
   ```
4. **生成**：
   ```bash
   npm run content:build
   ```
5. **确认生成物与测试**：
   ```bash
   npm run content:check
   npm test
   ```
6. **本地预览**：
   ```bash
   npm run serve
   ```
   打开 `http://localhost:8000/`，检查首页主题数、题目数、逐选项解析、错题本与内容版本。
7. **发布**：
   - 整站发布：部署 `demo/` 目录（含 `content/bundle.json`、`js/data.js`）。
   - 仅更新题库：替换线上 `content/bundle.json` 与 `content/manifest.json` 即可；在线用户下次打开即加载新题库。
   - 若希望离线用户也拿到新题库，需同时发布 `js/data.js`（通常随下一次应用发布）。
8. **回滚**：从 Git 恢复 `bundle.json` / `data.js` 后重新部署；内容源回滚后重新构建。

## 4. 更新节奏建议

| 频率 | 内容 | 版本位 |
| --- | --- | --- |
| 每 2 周 | 修正解析、补充错题、少量新题 | patch / minor |
| 每月 | 每主题新增 2–3 题、调整难度分布 | minor |
| 每季度 | 新增主题、重构课程结构 | major |

建议每次更新保持一个独立 commit，提交信息注明题库版本，例如：

```text
content: 题库 v2.1.0（新增网络排错题 6 道）
```

## 5. 新增主题

1. 新建 `demo/content/packs/<id>.json`，按 `SCHEMA.md` 填写 4 张知识卡与 15 道题。
2. 把文件加入 `manifest.json` 的 `packs`（顺序即首页展示顺序）。
3. 若使用新 `icon`，需要在 `demo/js/app.js` 的图标表中注册对应 SVG；复用现有图标则无需改代码。
4. 更新 `tests/content.test.js` 与 `tests/data.test.js` 中的主题列表/数量断言。
5. 执行完整校验、构建、测试与浏览器走查。

## 6. 内容质量检查清单

- [ ] 技术事实正确，命令、SQL、代码片段可复现。
- [ ] 每题只有一个正确答案，干扰项来自真实误区，不使用「以上都对」。
- [ ] `explanation` 解释原因，`optionNotes` 逐项说明对错。
- [ ] 难度分布：基础 ≥6、进阶 ≥4、挑战 ≥2；正确项 A–D 各 ≥2 且无连续 4 题相同。
- [ ] 题干、选项、解析为简体中文；术语首次出现附英文。
- [ ] 与已有题目不重复；代码/场景题达到每主题至少 2 道。
- [ ] 不复制受版权保护的题库原题。
