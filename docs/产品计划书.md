# 起点编程（DevStart）产品计划书

> 版本：v0.1 · 日期：2026-11-17 · 状态：MVP 计划 + 本地 Demo  
> 一句话：给零基础学习者的「计算机基础」学习与刷题训练场——用一张 10 分钟知识卡建立概念，用 8 道题验证掌握。

---

## 1. 背景与问题

### 1.1 目标用户

| 人群 | 典型画像 | 核心诉求 |
| --- | --- | --- |
| 在校学生（非科班 / 低年级） | 想补计算机基础，但课程偏理论 | 听得懂、有练习、能验证自己会没会 |
| 转行 / 跨专业自学者 | 跟着视频和文档学，路径零散 | 一条清晰的入门路线，知道下一步学什么 |
| 职场人补齐工程基础 | 工作需要接触 Python、Docker、K8s | 利用碎片时间，快速建立正确概念 |
| 培训班学员（次要） | 需要课后巩固与自测 | 按知识点刷题、看解析、反复练错题 |

共同特征：**时间碎片化、基础薄弱、对命令行和工程工具存在心理门槛**，需要的是「低门槛 + 短单元 + 即时反馈」，而不是又一套长视频课。

### 1.2 用户痛点

1. **路径乱**：资料太多，不知道先学什么、学到什么程度算入门。
2. **假懂**：看视频/读文档时觉得懂了，一动手或一做题就暴露漏洞。
3. **环境劝退**：Docker、K8s 等内容在「安装配置」阶段就流失大量新手。
4. **无反馈**：自学缺少判分和讲解，错了不知道为什么错。
5. **不复盘**：错题没有沉淀，学完就忘。
6. **算法平台不匹配**：主流刷题平台面向面试算法，不适合学习「容器、命令行、版本控制」这类基础概念。

### 1.3 现有方案与空位

- **视频课程**：系统但重，完课率低，缺少主动练习。
- **官方文档**：准确但面向查阅，不适合零基础线性学习。
- **算法刷题平台**：题目强、但偏算法面试，基础知识覆盖少。
- **零散博客 / 短视频**：获取快，但不成体系，质量参差。

空位：**面向「计算机基础概念」的轻量学习 + 刷题闭环**——每个知识点短、可练、有解析、能回炉，且不要求先搭环境。

## 2. 产品定位

### 2.1 价值主张

> **学一点，练一题，错题回炉。**  
> 每个主题由 3 张知识卡和 8 道题组成，10–20 分钟完成一次「学习 → 验证 → 复盘」闭环。

### 2.2 差异化

1. **内容聚焦基础概念**，不追算法竞赛，覆盖 Python / Docker / K8s / Linux / Git 等工程入门必备。
2. **知识与题目一一对应**：每张知识卡都有对应题目，刷题不是孤立测试，而是学习的一部分。
3. **零门槛**：Demo 为纯本地静态站点，双击即可打开，不上传数据、不注册账号。
4. **重反馈、轻打卡**：即时判分 + 解析 + 错题回顾，不制造学习焦虑。
5. **可验证的进度**：每个主题的最佳成绩、练习次数、完成度一目了然。

### 2.3 不做什么（MVP 边界）

- 不做视频课程、不做直播。
- 不做在线代码执行 / 容器沙箱（V2 再评估）。
- 不做社区、排行榜、付费体系。
- 不做「大而全」的百科，先把 5 个主题做扎实。

## 3. 目标与指标

### 3.1 阶段目标

| 阶段 | 目标 |
| --- | --- |
| Demo（当前） | 验证信息架构、学习闭环与刷题体验，可在本地完整走通 |
| MVP（公开试用） | 5 个主题、40 道题，形成可重复的「知识卡 → 刷题 → 结果页」流程 |
| V1 | 增加错题本、更多题目与主题，支持账号与多端同步 |
| V2 | 间隔重复、AI 讲解、交互式实验环境 |

### 3.2 指标体系

**北极星指标：每周完成至少一次完整练习（8 题）的用户数。**

| 指标 | 定义 | 早期目标（待校准） |
| --- | --- | --- |
| 激活率 | 访问首页 → 开始刷题 | ≥ 40% |
| 刷题完成率 | 开始 → 完成全部题目 | ≥ 60% |
| 首次正确率 | 首次作答正确题数 / 总题数 | 55%–75%（过低说明内容或题目有问题） |
| 错题回看率 | 结果页查看错题解析的比例 | ≥ 30% |
| 主题渗透 | 人均完成主题数 | ≥ 1.3 |
| 7 日留存 | 首访后 7 日内再次练习 | ≥ 15%（MVP 早期） |

> Demo 为纯本地版本，暂不上报数据；指标用于后续接入埋点后验证。

## 4. 内容体系

### 4.1 学科地图

**首批（MVP）**

| 主题 | 定位 | 知识卡 | 题目 |
| --- | --- | --- | --- |
| Python 编程基础 | 编程第一课：变量、控制流、函数 | 3 | 8 |
| Docker 容器入门 | 理解镜像 / 容器 / Dockerfile | 3 | 8 |
| Kubernetes 入门 | 集群、Pod、Deployment、Service | 3 | 8 |
| Linux 命令行基础 | 文件系统、常用命令、权限 | 3 | 8 |
| Git 版本控制 | 提交、分支、远程协作 | 3 | 8 |

**后续扩展方向**：计算机网络、数据库与 SQL、操作系统、数据结构、HTTP / Web 基础、CI/CD、云基础、安全常识。

### 4.2 学习单元结构

```
主题（Topic）
├── 知识卡 01：核心概念 + 类比 + 3–5 个要点
├── 知识卡 02：常见用法 / 操作
├── 知识卡 03：易错点与最佳实践
└── 刷题（8 题）：每题对应至少一张知识卡
```

设计原则：

- **一张卡只讲一个核心概念**，控制在 3–5 个要点，读完不超过 10 分钟。
- **题目必须能由知识卡支撑**，不考超纲细节。
- **解析讲「为什么」**，并说明主要干扰项错在哪。
- 术语首次出现时给出中文 + 英文，例如「容器（Container）」。

### 4.3 内容规范

| 项目 | 规范 |
| --- | --- |
| 题干 | ≤ 80 字，场景化或概念判断，一题只考一个点 |
| 选项 | 固定 4 个，长度接近，干扰项来自常见误解 |
| 答案 | 正确选项位置分散，避免连续同位置 |
| 解析 | 1–3 句，≤ 120 字，必须解释原因 |
| 难度 | MVP 以「基础」为主（约 80%），少量「进阶」（约 20%） |
| 编号 | 全局唯一，格式 `<topic>-<序号>`，如 `python-03` |
| 来源 | 自研题目，参考官方文档与经典教材，不直接复制题库 |

### 4.4 内容生产流程

1. 拟定主题大纲与知识卡要点。
2. 编写知识卡（概念 → 类比 → 要点 → 易错点）。
3. 按卡出题，标注对应关系与难度。
4. 交叉审校：技术准确性、表述清晰度、选项唯一正确。
5. 数据校验：ID 唯一、答案下标合法、解析非空。
6. 小范围试用，根据正确率与反馈迭代题目。

## 5. 功能规划

### 5.1 MVP（P0，Demo 已覆盖）

- 首页：产品介绍、学习路线、5 个主题入口、进度概览。
- 主题详情：知识卡阅读、学习进度、开始/继续刷题。
- 刷题：单选、逐题作答、提交后即时判分与解析、键盘操作。
- 结果页：得分、评语、错题回顾（你的答案 / 正确答案 / 解析）、重新练习。
- 本地进度：`localStorage` 保存最佳成绩与练习次数。
- 响应式布局（≥ 375px）与基础无障碍支持。

### 5.2 V1（P1）

- 全局错题本与「只练错题」模式。
- 更多主题与题库扩容（每主题 20+ 题）。
- 账号体系与多端进度同步。
- 题目收藏、笔记、反馈纠错入口。
- 学习连续天数（轻量，不做惩罚式打卡）。

### 5.3 V2（P2）

- 间隔重复（Spaced Repetition）排题。
- AI 讲解：针对错题生成类比与追问。
- Docker / K8s 交互式实验（浏览器内终端或托管沙箱）。
- 成就体系、学习报告、团队/班级模式。

### 5.4 优先级判断

| 功能 | 用户价值 | 成本 | 优先级 |
| --- | --- | --- | --- |
| 知识卡 + 刷题闭环 | 高 | 低 | P0 |
| 即时判分与解析 | 高 | 低 | P0 |
| 本地进度 | 中 | 低 | P0 |
| 错题本 | 高 | 中 | P1 |
| 账号同步 | 中 | 中高 | P1 |
| 题库扩容 | 高 | 中 | P1（持续） |
| 间隔重复 | 中高 | 中 | P2 |
| 交互式沙箱 | 高 | 高 | P2 |

## 6. 信息架构与核心流程

### 6.1 信息架构

```
首页（#/）
├── 课程主题卡片 → 主题详情（#/topic/:id）
│   ├── 知识卡 01–03
│   └── 开始刷题 → 答题（#/quiz/:id）
│       ├── 逐题作答 / 判分 / 解析
│       └── 结果页（得分 + 错题回顾）
├── 三步学习法（锚点）
└── 页脚：本地数据说明 / 清除进度
```

### 6.2 页面说明

| 页面 | 目标 | 关键模块 |
| --- | --- | --- |
| 首页 | 30 秒内理解产品并开始学习 | Hero、主题网格、三步学习法、进度摘要 |
| 主题详情 | 建立概念，形成刷题预期 | 面包屑、主题信息、知识卡序列、侧边进度与 CTA |
| 答题页 | 专注完成一次练习 | 题号进度、选项卡片、提交/下一题、即时反馈与解析 |
| 结果页 | 给出结论并促成复盘/重练 | 得分、评语、错题列表、重新练习、返回课程 |

### 6.3 刷题状态机

```
未选择 → 已选择 → 已提交（锁定选项，显示正误与解析）
                         ├── 非最后一题 → 下一题 → 未选择
                         └── 最后一题 → 结果页
结果页 → 重新练习 / 返回主题
```

关键约束：

- 提交前可更改选项；提交后锁定，防止「试出来」。
- 未选择时「提交答案」不可用。
- 最后一题按钮变为「查看结果」。
- 键盘 `1–4` 选择，`Enter` 提交 / 下一题。
- 结果页更新该主题 `bestScore`（仅在更高时覆盖）、`attempts`、`lastScore`。

### 6.4 进度存储

- Key：`devstart:progress:v1`
- 结构：`{ [topicId]: { bestScore, total, attempts, lastScore, updatedAt } }`
- 仅保存在浏览器本地；清除进度需二次确认。

## 7. 体验与设计原则

1. **一屏一件事**：答题页只保留当前题目与必要操作，减少干扰。
2. **反馈必须明确**：正误不能只靠颜色，配图标与文字标签；解析紧随答案出现。
3. **进度可见**：题号、进度条、已得分三处提示当前位置与表现。
4. **鼓励而非训斥**：结果文案按分数分档，低分给出下一步建议而非负面评价。
5. **移动优先**：选项为大点击区，单手可完成整套练习。
6. **轻动效**：过渡服务于状态变化，尊重 `prefers-reduced-motion`。
7. **本地优先**：所有数据留在本机，明确告知用户。

## 8. 技术方案

### 8.1 Demo 技术选型（已采用）

- 纯静态：HTML + CSS + 原生 JavaScript，**无构建、无依赖、无 CDN**。
- 直接双击 `demo/index.html` 即可运行（兼容 `file://`），也可用任意静态服务器托管。
- 路由：`hash` 路由（`#/`、`#/topic/:id`、`#/quiz/:id`），支持刷新与前进/后退。
- 数据：`js/data.js` 内置 5 个主题、15 张知识卡、40 道题，浏览器与 Node 双端可读。
- 逻辑：`js/quiz-core.js` 提供纯函数 `gradeQuiz(questions, answers)`，便于单元测试。
- 存储：`localStorage`，无后端、无账号。

选择理由：Demo 的核心是验证学习闭环与交互，静态方案交付快、可离线演示、便于评审；同时把数据与判分逻辑独立出来，后续迁移到正式技术栈时可直接复用。

### 8.2 生产架构建议

| 层 | 方案 | 说明 |
| --- | --- | --- |
| 前端 | Astro（内容优先）或 Next.js | 静态生成课程页，利于 SEO 与首屏性能 |
| 内容 | 仓库内 JSON / MDX + Schema 校验 | 内容即代码，便于评审与版本化 |
| 后端 | Supabase / Postgres + Auth | 账号、进度、练习记录 |
| 判分 | 服务端校验答案 | 防止前端篡改；本地模式可离线 |
| 分析 | 轻量埋点（Plausible / 自建） | 关注完成率、正确率、留存 |
| 部署 | Vercel / Cloudflare Pages | 静态优先，低成本 |

### 8.3 数据模型（建议）

```text
topics(id, slug, title, tagline, level, accent, sort_order)
cards(id, topic_id, sort_order, title, summary, points_json)
questions(id, topic_id, card_id, difficulty, stem, options_json,
          answer_index, explanation, version, status)
quiz_sessions(id, user_id, topic_id, score, total, started_at, finished_at)
answers(session_id, question_id, selected_index, is_correct, answered_at)
user_progress(user_id, topic_id, best_score, attempts, updated_at)
```

### 8.4 质量保障

- **数据校验**：主题数、卡片数、题目数；ID 唯一；每题 4 个选项；`answerIndex` 合法；解析非空。
- **判分单测**：全对、全错、部分正确、空答案、缺省答案、百分比取整。
- **冒烟检查**：入口文件存在、脚本按序引入、无外链依赖、无 ES Module（保证 `file://` 可用）。
- **手工走查**：首页 → 主题 → 刷题 → 结果 → 重练 → 返回，含刷新与移动端宽度。
- **可访问性**：键盘全流程、焦点可见、`aria-live` 反馈、对比度检查。

## 10. 里程碑

> 估时按「1 名开发者 + AI 辅助，设计/内容兼职」计算。AI 能直接生成代码与初稿，时间主要花在**内容审校、设计取舍、真实用户测试**这些无法完全外包的环节。

| 阶段 | 内容 | 预估 | 瓶颈 |
| --- | --- | --- | --- |
| Demo（已完成） | 计划书 + 5 主题 + 刷题闭环 + 测试 | 1 个工作日内 | 内容准确性与交互细节审校 |
| 内测准备 | 内容二审、5–10 人走查、修复高优问题 | 2–3 个工作日 | 招募测试者、收集反馈 |
| 公开 MVP | 域名部署、基础埋点、反馈入口、错题本雏形 | 3–5 个工作日 | 部署与隐私合规确认 |
| V1 | 账号同步、题库扩容至 100+ 题、更多主题 | 1–2 周（AI 辅助） | 内容生产与审校占大头 |

**结论**：开发与页面实现不再是主要成本；**内容质量、学习效果验证和用户反馈闭环**决定项目进度。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 技术内容出错 | 误导用户、损害信任 | 双人审校；标注参考来源；页面提供纠错入口；题目带版本号 |
| 题目质量参差（歧义、多解） | 正确率失真、用户困惑 | 出题规范 + 数据校验 + 小范围试测；错误题目快速下线 |
| 与大平台同质化 | 难以获得用户 | 聚焦基础概念与短闭环；强化错题回炉与后续实验能力 |
| 留存不足 | 学完即走 | 短单元、可见进度、错题本、适度提醒；不依赖打卡焦虑 |
| 范围膨胀 | 交付延期 | MVP 锁定 5 主题 / 40 题；新需求进入 V1 清单 |
| 环境类内容无法实操 | 学习效果有限 | MVP 明确「概念入门」边界；V2 引入沙箱或托管实验 |
| 题库维护成本 | 内容陈旧、链接失效 | Schema 化 + CI 校验；内容与代码同仓版本管理 |
| 版权问题 | 法律风险 | 全部自研题目与表述；引用注明出处；不使用未授权图片 |

## 12. 运营与增长（简）

1. **冷启动**：校园社团、转行社群、技术社区发布「Linux / Git 入门 8 题自测」。
2. **内容获客**：每个主题可生成独立分享页与「错题解析」短文，承接搜索流量。
3. **反馈飞轮**：题目纠错入口 → 快速修订 → 版本记录公开，建立可信度。
4. **留存设计**：完成后推荐「下一主题」，结果页展示进步曲线（V1）。
5. **合作**：与培训班/高校课程合作，作为课后自测工具（V1 之后）。
